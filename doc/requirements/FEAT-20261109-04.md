## 1.需求

### 目标

为 Melt Party（https://melt.party，科技户外运动装备电商，默认主题 glacier-night：底 `#0b1117`、主色冰川青 `#4fd6e8`、强调荧光绿 `#c8ff3d`）设计原创品牌 Logo 与全套网站图标，并接入站点。

### 现状（基线 e1c2a23）

- `app/favicon.ico` 是 Create Next App 默认图标。
- `public/logo.svg` 是临时方块字「MELT/PARTY」+ 绿条。
- `lib/store-config.ts` 的 `theme.logoPath` 默认 `/logo.svg`（可被 `NEXT_PUBLIC_STORE_LOGO_PATH` 覆盖），仅 `components/agent/AgentDrawer.tsx` 引用；后台 `KnowledgeManagement.tsx`、`ProductEditor.tsx` 直接引用 `/logo.svg`。
- 页头只显示店名文字；后台侧栏用橙色方块 + 店名首字母。
- 没有 apple-touch-icon、PWA manifest、OG/Twitter 分享图。

### 范围

1. 原创 Logo：先出 2–3 个方向，按辨识度、16px 可读性、与 glacier-night 协调度打分选定。
2. 产出：
   - 图形标 mark（正方形）：深底版、透明底版。
   - 横版组合标（mark + 「Melt Party」字标）：深底浅色版、浅底深色版。
   - 全部 SVG 为干净矢量：无位图嵌入、无 `<text>`，字标全部是路径。
3. 图标套件：`favicon.ico`（16/32/48）、`icon.svg`、apple-touch-icon 180、PWA 192/512 与 maskable 512（安全区留白）、Web App Manifest（name/short_name/theme_color/background_color 与主题一致）、OG/Twitter 分享图 1200×630（Logo + 站名，深色）。
4. 按 Next 16.3.4 的 app 目录元数据文件约定放置，替换默认 favicon。
5. 引用 logoPath 或旧 logo 的位置统一换新；后台侧栏换新图形标，但保持后台原配色。
6. 确认中间件/路由不拦截 `/favicon.ico`、`/icon.svg`、`/apple-icon.png`、`/manifest.webmanifest`、`/opengraph-image.png`、`/twitter-image.png` 与 `public/` 下的图标路径。
7. 栅格图由 SVG 经脚本生成，脚本放 `scripts/`，生成物提交入库；预览拼图存 `~/Workspace/evidence/mercora/brand-icons-20261109/`。

### 非目标

- 不改主题 token、主题 CSS、`lib/themes/manifest.generated.ts`、`themes/index.generated.css`。
- 不改后台配色，不改邮件模板版式（邮件模板当前不引用任何 Logo 文件）。
- 不按「当前激活主题」动态换色图标：图标是品牌资产，固定用 glacier-night 品牌色。
- 不新增依赖；不部署。

### 验收标准

1. `app/favicon.ico` 含 16/32/48 三个尺寸，且不再是 Next 默认图标。
2. 页面 `<head>` 输出 favicon、icon.svg、apple-touch-icon、manifest、og:image、twitter:image。
3. Manifest 的 `name`/`short_name` 取店铺配置，`theme_color`/`background_color` 取 glacier-night 的 surface 色，包含 192/512 与 maskable 512 图标。
4. maskable 图标主体落在中心 80% 安全区内。
5. 16/32px 渲染图经人工看图确认可辨识。
6. 所有 SVG 不含 `<image>`、`<text>`、base64。
7. `npm run build:themes:check`、`scan:tokens`、`lint`、`typecheck`、`test` 通过，`npm run build` 尽量通过。

## 2.分析过程

### 设计方向与打分

用同一套 512 网格分别渲染 256/64/32/16px 对比（拼图 `~/Workspace/evidence/mercora/brand-icons-20261109/directions-explore.png`），每项 1–5 分：

| 方向 | 描述 | 辨识度 | 16px 可读 | 与 glacier-night 协调 | 合计 |
|---|---|---|---|---|---|
| A 融峰 | 单峰 Λ + 峰内荧光绿水滴 | 3（易读成字母 A，和品牌名无关） | 4 | 4 | 11 |
| B 对称 M | 竖直双竖笔 M + 山谷下垂水滴 | 3（通用 M 字形，缺山的意象） | 5 | 4 | 12 |
| **B2 山脊 M** | **左高右低的不对称双峰山脊连成 M，山谷正下方悬一滴融水** | **5（M 首字母 + 山脊 + 融化三重含义）** | **4** | **5** | **14** |
| C 信号滴 | 水滴轮廓内套荧光绿山峰 | 3（水滴标志在水务/饮料行业常见） | 3（内部 V 在 16px 糊成一团） | 4 | 10 |

选定 B2：冰川青山脊 = 店铺品类（户外/山地）+ 店名首字母 M；荧光绿水滴 = 「Melt」，同时复用主题里唯一的强调色；斜接尖峰与平截底边呼应 glacier-night 「精密仪器、线条利落」的设计意图。

### 关键决策

- **几何全部由脚本计算**：本机没有 rsvg-convert / Inkscape，也不能让 SVG 依赖字体。字标「MELT PARTY」是自绘的几何无衬线大写字母，由矩形、两端水平截平的斜笔画、evenodd 挖空的半圆碗组合成填充路径，没有 `<text>`、`<image>`、base64；栅格图用仓库已有依赖 sharp（libvips 内置 librsvg）渲染，不新增依赖。
- **16px 可读性**：初版山谷斜接尖角离水滴太近，16px 下荧光绿像素与冰川青相连，像一根延长的竖笔。抬高山谷（y 250→228）、水滴下移，并给 16/32px 单独出「圆角更小、图形更满（0.84）」的变体，放大检查确认山谷与水滴之间留出一行暗像素。
- **字距**：等距排列时 L-T、T-Y 之间视觉空洞明显，加了 5 组字距修正。
- **文件约定（Next 16.3.4，读 `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/`）**：`app/favicon.ico`、`app/icon.svg`、`app/apple-icon.png`、`app/opengraph-image.png`、`app/twitter-image.png`（+ `.alt.txt`）用静态文件约定，由 Next 自动输出 head 标签；manifest 用 `app/manifest.ts`。
- **manifest 用 TS 而不是静态 JSON**：`name`/`short_name` 取 `getStoreConfig().identity.name`，保持「店名可配置」的既有约定；颜色取 `getThemeTokens("glacier-night").surface`，不在 `app/` 写 hex（`scan:tokens` 扫描 app 目录）。颜色固定跟 glacier-night 而非当前激活主题，因为图标本身是 glacier-night 品牌色，启动画面底色要与图标一致。仿照 `app/robots.ts` 设 `force-dynamic`，运行时读环境变量。
- **icon.svg 不加 prefers-color-scheme**：图形标自带深色圆角底板，在浅色和深色标签栏上都清楚，加媒体查询反而要多维护一套配色，收益为零。
- **apple-icon 满版不圆角**（iOS 自己加遮罩）；maskable 图形外框占 60%，实测图形像素离中心最远 197px，小于安全圆半径 204.8px。
- **favicon.ico** 用 PNG 内嵌的 ICO（16/32/48），脚本手写 ICO 头，不引新库。
- **接入位置**：页头 Logo 链接加 `store.theme.logoPath` 图形标（32px，alt 为空，旁边已有店名文字）；后台侧栏原「橙色方块 + 首字母」换成 `logoPath` 图形标，侧栏其余配色不动；`public/logo.svg`（logoPath 默认值）换成新图形标，因此 AgentDrawer 与后台两处 `/logo.svg` 引用自动换新。邮件模板不引用任何 Logo 文件，不改。
- **路由与中间件**：`middleware.ts` matcher 已排除 `.png/.svg/.ico/.webmanifest` 结尾的路径，上述图标路径都不进中间件，无需改动。

### 已踩坑

- `next start`/`next dev` 没有 Clerk publishable key 时中间件直接 500；本地验证用格式合法的假 key。假 key 下浏览器文档请求会被 Clerk 握手重定向到外部域名，截图时改用无浏览器请求头的 fetch 取主文档并中止外部请求。
- `next start` 没有 Cloudflare 上下文，首页因 D1 查询 500（与本需求无关，`/sign-in` 200）；页头效果改用 `npm run dev`（本地 D1）验证。
- 静态 `favicon.ico` 的 head 标签 `sizes` 由 Next 取 ICO 第一项，输出为 `16x16`；浏览器会解析整个 ICO 选尺寸，且同时输出了 `sizes="any"` 的 icon.svg，不影响使用。

## 3.完成的过程

### 改动

- 新增 `scripts/generate-brand-assets.mjs`：几何定义 → SVG 源文件 + 全部栅格图；`--preview <dir>` 额外输出预览拼图。重复运行生成物逐字节一致（shasum 比对）。
- Logo 源文件（`public/brand/`）：`mark.svg`（深底）、`mark-transparent.svg`（透明底）、`logo-horizontal-dark.svg`（深底浅色字）、`logo-horizontal-light.svg`（透明底深色字，图形标带深色底板）。
- 图标套件：`app/favicon.ico`（16/32/48）、`app/icon.svg`、`app/apple-icon.png`（180）、`public/icons/icon-192.png`、`icon-512.png`、`maskable-512.png`、`app/manifest.ts`、`app/opengraph-image.png`、`app/twitter-image.png`（1200×630）及两个 `.alt.txt`；`public/logo.svg` 换新。
- `components/HeaderClient.tsx` 页头加图形标；`components/admin/AdminSidebar.tsx` 侧栏换图形标。
- `tests/unit/app/manifest.test.ts`：manifest 取店名与 glacier-night surface 色、图标清单。

### 验证

- `npm run build:themes:check`、`npm run scan:tokens`（0 violations）、`npm run lint`（0 error，警告均为既有文件）、`npm run typecheck`、`npm test`（330 文件 / 3022 用例通过，含新增 manifest 测试）、`npm run build` 通过；build 路由表含 `/apple-icon.png`、`/icon.svg`、`/manifest.webmanifest`、`/opengraph-image.png`、`/twitter-image.png`。
- `next start` 实测 14 个路径全部 200 且 Content-Type 正确：`/favicon.ico`、`/icon.svg`、`/apple-icon.png`、`/manifest.webmanifest`、`/opengraph-image.png`、`/twitter-image.png`、`/icons/*.png`（3 个）、`/logo.svg`、`/brand/*.svg`（4 个）；`/sign-in` 页面 head 含 favicon、icon.svg、apple-touch-icon、manifest、og:image、twitter:image 标签。
- 人工看图：16/32/48px 放大图、apple/PWA/maskable（圆形遮罩）、组合标、分享图，以及 `npm run dev` 下桌面与 375px 页头截图，均存 `~/Workspace/evidence/mercora/brand-icons-20261109/`。
- 所有 SVG 经 grep 确认不含 `<text>`、`<image>`、base64。
