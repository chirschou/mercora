## 1.需求

### 目标

`NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` 与 `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` 不再写入仓库，改由 Workers Builds 的 Build variables（或本机手工构建时的 shell 环境）提供。

### 范围

- 从 `wrangler.jsonc` 的 `vars` 移除上述两项，并重新生成 `cloudflare-env.d.ts`。
- `scripts/build-with-public-env.mjs`：缺少 Clerk 公钥时中止构建。
- 同步 `docs/runtime-configuration.md`、`docs/DEPLOYMENT_SETUP.md`、`.env.example`。

### 非目标

- 不改 Worker 名、资源 ID，不写任何真实 key，不执行 deploy、deploy:ci、迁移，不改 `lib/stripe.ts`（缺 Stripe 公钥仍只告警）。

### 验收标准

1. `wrangler.jsonc` 中不含两项公钥；`npm run cf-typecheck` 通过。
2. 设置 Clerk 公钥、不设 Stripe 公钥时 `npm run build:worker` 成功。
3. 不设 Clerk 公钥时 `build-with-public-env.mjs` 以退出码 1 中止（测试覆盖，去掉检查则报红）。

## 2.分析过程

- `build-with-public-env.mjs` 把 `wrangler.jsonc` 的 `NEXT_PUBLIC_*` 覆盖进构建环境；键被移除后自然回落到构建环境变量，无需改变覆盖逻辑。
- 实测：不设 Clerk 公钥时 `build:worker` 仍然成功（退出码 0），产出的站点运行时无法登录，属于静默产出坏包，因此在包装脚本中加了检查。检查只看进程环境：Next 构建本就不读 `.dev.vars`，仅放在 `.dev.vars` 的本地构建此前同样得不到该公钥。
- Stripe 公钥缺失时 `lib/stripe.ts` 只告警、构建成功，不加检查（非本次范围；仅文档提示）。
- `.planning/` 与旧需求文档里的公钥记述不改。
- 未触及应用代码（app/ lib/ components/）；`scripts/` 与 `tests/` 属构建脚本与测试。
