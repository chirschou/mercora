## 1.需求

### 目标

1. **品牌改名**：平台名 Mercora 和样例店名 Voltique 统一改为 Melt Party，域名改为 melt.party。
2. **助手改名、换 Logo**：AI 助手 Volt 改名为 **Floe**。助手头像（即 `theme.logoPath`）换成新的 Melt Party 文字型 SVG。
3. **新主题设为默认**：新增深色科技户外运动主题 `glacier-night`（标签 Glacier Night），设为默认主题。`volt-dark` 保留为普通预设，不改名，也不再是默认。

- 自带底板，所以在 8 个预设的任意表面上都可读。它是品牌资产，不走 token：`scan:tokens` 只扫 `app/`、`components/`、`lib/`、`themes/`、`tailwind.config.ts` 下的 `.ts/.tsx/.css` 文件，不扫 `public/`。

### 现状证据

- **默认主题由谁决定**：`getActiveTheme()` 按以下顺序解析：
  1. D1 的 `appearance.theme`；
  2. `NEXT_PUBLIC_THEME_DEFAULT`（必须是 manifest 中的名字）；
  3. manifest 的 `DEFAULT_THEME_NAME`。

  `DEFAULT_THEME_NAME` 的源头是 `scripts/build-themes.mjs:29` 的常量，生成进 `manifest.generated.ts`。`git grep appearance -- migrations data scripts` 确认**没有任何迁移或种子写入 `appearance.theme`**（`admin_settings` 的种子只有 0011、0017 两条无关设置），所以切换默认不需要迁移。`getThemeTokens()` 不传参时（`global-error`、邮件、Stripe、Clerk 的回退）以及管理端 `ThemePresetGrid` 的回退也都读 `DEFAULT_THEME_NAME`。改一处常量再重新生成，就全部跟着变。
- **wrangler 变量在开发态不生效**：据 FIX-20261108-01 的核实，`next dev` 不会把 `wrangler.jsonc` 的 `vars` 注入 `process.env`，只有 `build:worker` 会注入。所以本地默认主题取决于 manifest 常量，生产取决于 wrangler 变量。两处都必须改，这就是验收第 4 条一致性测试要防的事。
- **对比度没有自动门禁**：`scripts/scan-hardcoded-colors.mjs` 只查硬编码色值，`git grep -i -e contrast -e wcag -- tests scripts lib` 只命中生成的 manifest（主题文件头的文字）。派单所说的「scan:tokens（含对比度）」与事实不符，改为验收第 5 条的人工计算。
- **荧光绿强调能放在哪**：23-token 契约冻结，没有 accent token。店面里 `text-success` 有 25 处（含「In Stock」），`ring` 用于焦点（`focus-visible:ring-ring/50` 等）。所以荧光绿放在 `ring` 和 `success` 上；CTA 按钮用主色青。
- **persistence 配置值没人消费**：`lib/stores/cart-store.ts:365` 和 `chat-store.ts:83` 的 persist 名分别是 `cart-storage`、`chat-storage`。`StoreConfig.persistence` 在店面代码里没有消费方。真正带品牌词的浏览器键只有 `lib/checkout/order-payload.ts` 的 `mercora:pending-checkout:` 前缀。
- **Logo 实际用途**：`theme.logoPath` 只在 `components/agent/AgentDrawer.tsx` 里作助手头像用（40px 和 20px）。页头显示的是文字店名（`HeaderClient.tsx`）。两个管理端组件写死了 `/volt.png`。`data/r2/volt.svg` 是 1024² 的位图封装 SVG，代码里没有任何引用。
- **About 页内容来自已应用迁移**：`0003_add_cms_pages.sql:156` 向 `pages` 写入 About 页，正文里有 `Mercora` 两处、`assistant Volt` 一处。`pages.updated_at` 是 `INTEGER DEFAULT (unixepoch())`。迁移安全检查只拦 DROP、RENAME、DELETE FROM，UPDATE 不受限，新增迁移可以过 `check:migrations`。
- **冻结向量**：`code.test.ts:120`（digest）和 `encryption.test.ts:70`（ciphertext）的期望值依赖域串，改名后必然变。
- **storeDefaults 是占位值**：`docs/runtime-configuration.md` 写明它是「neutral demo defaults」。真实域名只放部署配置（`wrangler.jsonc` 的 vars）。
- **样例目录不会自动导入**（基线状态）：`predev` 只执行迁移和 `seed-dev.sql`。`seed.sql` 用的是普通 INSERT，重复执行会失败。FIX-20261108-01 正在修这个问题。

### 证据：HMAC 向量（验收第 8 条）

独立实现与被测实现（WebCrypto）无关：digest 用 Python 标准库 `hmac` 和 `openssl dgst`，AEAD 用 Apple CryptoKit（Swift）。消息构造按源码：digest 为 `[HMAC_PURPOSE, "digest:v1", "key:2", code].join("\0")`；AEAD 的 AAD 为 `[AEAD_PURPOSE, "aead:v1", "key:1", "gift-card:gift_card_01JABC", "delivery:delivery:01JXYZ"].join("\0")`，密钥为字节 0..31，nonce 为字节 0..11，输出 `ciphertext||tag` 的 base64。脚本在 `/tmp/feat02-vectors/`（未入库）。

先用旧域串复现旧向量（证明消息构造与源码一致），再算新域串：

```text
$ python3 -I /tmp/feat02-vectors/digest.py "mercora:gift-card:bearer-code"
mercora:gift-card:bearer-code df3906d559ae28e67336f983afbb989f974974d3a5bf2f006e30719de68fc566   # 与旧冻结值一致
$ python3 -I /tmp/feat02-vectors/digest.py "melt-party:gift-card:bearer-code"
melt-party:gift-card:bearer-code 60509389d1fe48ecf35b644dd9c2ab2bba74d00247d409d64fb63f002b8e4e18
$ printf 'melt-party:gift-card:bearer-code\0digest:v1\0key:2\0GC-2345-6789-ABCD-EFGH-JKLM-NPQR-STUV' | openssl dgst -sha256 -hmac 'current-gift-card-hmac-key-material-0001' -r
60509389d1fe48ecf35b644dd9c2ab2bba74d00247d409d64fb63f002b8e4e18 *stdin
$ swift aead.swift "mercora:gift-card:delivery-code"
mercora:gift-card:delivery-code AEH7KfbR9za7dq+ynKg6Lsf7wnK3M3I2cyuoqFM5UeAsQ/qp+bTs7joq6camMJtRdiKOhME=   # 与旧冻结值一致
$ swift aead.swift "melt-party:gift-card:delivery-code"
melt-party:gift-card:delivery-code AEH7KfbR9za7dq+ynKg6Lsf7wnK3M3I2cyuoqFM5UeAsQ/qp+Sli0pZk6DOlAQXLoiBzhJY=
```

AAD 只影响 GCM 标签，所以新旧输出前 37 字节（明文长度，CTR 加密部分）相同、只有末尾 16 字节标签不同（已用 Python 解码核对），符合预期。

改名前后各跑一次：

- 旧向量 + 新域串：`npx vitest run tests/unit/lib/gift-cards/code.test.ts tests/unit/lib/gift-cards/encryption.test.ts` → `Tests 2 failed | 96 passed`，失败的正是两个冻结用例（实际值与上面独立计算的新值相同）。
- 写入新向量后：`npx vitest run tests/unit/lib/gift-cards/` → `Test Files 20 passed`，`Tests 326 passed`。

`lib/gift-cards/capability.ts` 的预留 ID 域串 `melt-party:gift-card:reservation` 没有冻结向量（`capability.test.ts` 用的是固定的 `gift_reservation_one`），无需重算。
