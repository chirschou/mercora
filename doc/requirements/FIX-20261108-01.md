## 1.需求

### 现象

在干净检出上执行 `npm run dev` 后：

1. 本地 D1 只有迁移和 `data/d1/seed-dev.sql`（MCP 测试凭据、`dev-order-001` 订单夹具），没有商品与分类。首页没有商品，`/category/*` 返回 404。
2. 手动执行 `npx wrangler d1 execute mercora-db --local --file=data/d1/seed.sql` 导入目录后，首页、分类页、商品页的商品图片全部不显示。浏览器请求的是 `/products/<文件>.png`，返回 404。
3. 即使再手动把图片写进本地 R2，商品图片仍然 404。原因是开发模式下 loader 不会把图片地址映射到 `/media/<key>`。
4. 分类页头图（`app/category/[slug]/page.tsx`）不经过本地 R2，硬编码请求上游作者的外部域名 `https://voltique-images.russellkmoore.me/<key>`。它现在能显示，只是因为该外部域名恰好可访问。

### 现状证据

- **loader 根因**：`image-loader.ts` 在 `NODE_ENV === "development"` 时直接 `return src`。src 来自 `resolveProductImageSrc`，形如 `/products/x.png`（R2 键前补一个 `/`），开发模式下就按这个路径原样请求。项目里只有 `/media/[...key]` 路由会读 R2，`/products/*` 没有任何路由或 `public/` 文件提供，所以 404。生产不配置 CDN 时输出 `/media/<key>`（现有单测已覆盖）。
- **`/media` 路由的 Content-Type 校验**：`verifiedContentType` 要求对象声明的 `httpMetadata.contentType` 与扩展名一致，否则返回 404。
- **seed.sql 可用性**：在临时持久化目录（`--persist-to /tmp/...`，只用 `--local`）实测：全新库上先应用迁移再执行 `data/d1/seed.sql`，成功，得到 products=33、categories=9、product_variants=37、pricing=33、inventory=32。第二次执行报 `UNIQUE constraint failed: categories.id`，退出码非 0。`.planning/` 里说 seed.sql 的 products 批量 INSERT 列数不齐、已损坏，这个说法已过时，以本次实测为准。
- **原子性**：本地 `wrangler d1 execute --file` 中途失败会整体回滚（用 `a`、`b`、重复 `a` 三条 INSERT 实测，最终 0 行）。
- **样例图覆盖**：seed.sql 引用了 45 个 `products/`、`categories/` 键，`data/r2/` 下都有对应文件。`data/r2/{products,categories}` 实际有 48 个 png，约 105MB；多出来的 3 个是 `products/placeholder.png`（ProductCard 的兜底图）、`products/rapid-wave-kit-6a.png`、`categories/hydration.png`。`data/r2/` 下另有 `products_md/`、`knowledge_md/`、`volt.svg`，属于 AI 索引内容，不在本 FIX 范围。
- **wrangler 能力**（4.129.0）：
  - `r2 object put` 和 `r2 bulk put`（`--filename` 接收 `[{key,file}]` JSON，默认并发 20）都支持 `--local`、`--persist-to`、`--content-type`。
  - 没有 `r2 object head` / `list`。
  - 单次 `d1 execute --local --command` 约 0.5 秒。本机首次冷启动时，`migrations apply` 约 38 秒，执行 seed 文件约 67 秒，CPU 占用都很低，原因未查明。

### 决策缘由与已踩坑

- **坑 1：R2 写入不带 `--content-type` 会被当成 404。** 实测 `r2 object put` 和 `r2 bulk put` 不带 `--content-type` 时，本地对象的 `http_metadata` 都是 `{}`。`/media` 路由的 `verifiedContentType` 因此返回 null，图片 404。导入必须按扩展名显式传 Content-Type。`bulk put` 只接受一个全局 `--ct`，所以要按扩展名分组调用（目前只有 png）。
- **坑 2：seed.sql 不能每次启动都执行。** 它的批量 INSERT 是普通 INSERT，只有末尾的礼品卡块是 `INSERT OR IGNORE`，重复执行会让 predev 失败，必须加判定。
- **坑 3：dev-seed-guard 的单引用约束。** `data/d1/seed-dev.sql` 的路径字面量在 `scripts/` 下只能出现在一个文件里。抽到 `scripts/lib/` 的纯函数不得包含这个路径字符串，seed.sql 的路径不受这条约束。
- **坑 4：rewrite 方案的路由冲突**，见「已决定事项」第一行。
- **坑 5：开发与生产持久化必须一致。** 导入必须写入 dev server 读取的同一个本地状态目录。wrangler CLI 和 `getPlatformProxy` 默认都用 `.wrangler/state/v3`，predev 不要传自定义 `--persist-to`。临时目录只用于本次验证。
- **坑 6：本机默认 node 不可用。** 本机默认 `node`（Homebrew node 26）缺 `libsimdjson` 动态库，无法运行。验证时用 `/opt/homebrew/opt/node@24/bin`（v24.22.2）。实现阶段要按 `.node-version` 的 24.18.1 跑门禁。
- **待决 1–3 的决定（编排方按用户授权代决，2026-11-08）**：
  - 待决 1 选 A：纳入本 FIX。分类头图的相对键改为根相对路径，交给 loader 统一映射。已带前导 `/` 的键原样返回，避免拼出 `//x` 这种协议相对 URL。新增单测证明：在当前生产 CDN（`https://voltique-images.russellkmoore.me`）下，新旧写法的 loader 输出逐字相同。
  - 待决 2 选 A：每次 predev 都全量执行 `r2 bulk put --local`，不逐对象 get。必须按扩展名显式传 `--content-type`（见坑 1）。
  - 待决 3 选 A：删除 `image-loader.ts` 中 `NODE_ENV === "development"` 的提前 return，开发与生产共用同一套映射。
  - seed.sql 导入挂在 `scripts/db-local-ensure.mjs` 内，只在 `products` 为空时执行。依赖 `d1 execute --file` 失败整体回滚，保证幂等。不新增单独的 seed 命令。
- **实现取舍**：
  - 判定逻辑与参数构造放在纯函数模块 `scripts/lib/local-sample-plan.mjs`。该模块不含 `seed-dev.sql` 路径（坑 3）。
  - 扩展名到 Content-Type 的映射在脚本模块里另存一份，由单测解析 `app/media/[...key]/route.ts` 源码比对。没有改成共享模块，因为 Next 路由文件不能导出额外符号，而 `.mjs` 脚本也不便直接 import TS。
  - 计数查询用 `--json` 输出，解析失败、结构缺失、非非负整数都直接中止 predev，并给出明确报错，不会当作空库处理。
  - 计数 SQL 用 `--command` 执行。wrangler 失败时抛错，由外层统一按原退出码退出，保证 finally 能清理 bulk put 的临时清单目录。
  - 新增日志沿用该脚本现有的英文风格，与仓库内其他英文文档保持一致。
- **执行顺序**：迁移 → （products 为空时）`seed.sql` → `seed-dev.sql`（每次都执行，本身幂等）→ R2 样例图。seed.sql 与 seed-dev.sql 写的表互不重叠（目录表对 `mcp_agents`、`orders`），顺序不影响结果。目录判定要在迁移之后做，保证表已存在。

### 风险与控制

- **首启耗时**：在现有迁移之外，增加一次计数查询（约 0.5 秒）、首次的 seed 导入，以及一次 bulk put（约 1.3 秒）。二次启动的增量约 2 秒（若选待决 2-B，R2 部分接近 0）。
- **误写远端**：所有 wrangler 参数都由纯函数生成，并有单测断言必带 `--local`、不带 `--remote`（验收第 2、4 条）。
- **覆盖本地改动**：待决 2-A 会覆盖与样例图同名的本地对象，影响面限于开发者在本地 admin 上传了同名文件的情况。
- **生产回归**：loader 的生产分支不改，现有 6 个单测守住（验收第 3 条）。待决 1-A 在当前生产 CDN 配置下输出逐字相同，详见待决 1。
