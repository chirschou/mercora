## 1.需求

### 现象

`app/layout.tsx` 用 `next/font/google` 加载 Cormorant Garamond、Fraunces、Geist、Geist Mono、Nunito、Orbitron。构建时 Next 的字体加载器要访问 `fonts.googleapis.com` 拿 CSS，再从 `fonts.gstatic.com` 下载字体文件。Google 偶尔返回不带扩展名的 `/l/font?kit=...` 地址，加载器里的 `/\.(woff|woff2|eot|ttf|otf)$/.exec(url)[1]`（`node_modules/next/dist/compiled/@next/font/dist/google/loader.js`）匹配失败，直接抛错，构建失败。Workers Builds 构建 d9c17a21 因此失败；编排方本机曾连续重试 Nunito 5/5 复现。

### 复现步骤

Google 返回什么由对方决定，本任务实现时（2026-11-09）多次请求，返回的都是正常的 `.woff2` 地址，`/l/font?kit=` 无法稳定复现。按派单约定，改用可验证的断言：**构建不再访问 fonts.googleapis.com / fonts.gstatic.com**。

1. 在基线 `d8463bc` 上，用进程级钩子（见 3. 完成的过程）让这两个域的 DNS 解析返回 ENOTFOUND，不改系统全局配置。
2. 执行 `NODE_OPTIONS="--require <钩子>" NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_placeholder npm run build:worker`。

### 范围与非目标

- 非目标：不改主题 CSS 及其生成物、CSS 变量名、`app/globals.css`；不新增字体或字重；不改 CSP；不部署。

4. 新单测在基线 `app/layout.tsx` 上报红，修复后通过。

## 2.分析过程

- **字体文件来源：直接用 Google 当前提供的文件，不另行转换**。按改前 `next/font/google` 实际发出的请求（`css2?family=<Family>:wght@<weights>&display=swap`，User-Agent 为 Chrome/104，见 `fetch-resource.js`）去拿 CSS。结果是每款字体每个子集一个可变 woff2，多个字重共用同一个文件。latin 子集的这 6 个文件和改前构建产物 `.next/static/media` 中的文件 sha256 逐字节一致，渲染等价不需要额外论证，也不需要引入 fonttools 之类的转换工具。
- **为什么要显式声明 `unicode-range`**：用 Next 自带的 fontkit 读这 6 个文件的 cmap，发现它们收录了 latin 范围以外的码点（如 U+0102、U+0300–0303、U+0309、U+0323）。如果不声明 `unicode-range`，这些字符会改由 latin 文件渲染，结果和改前不同。所以每个 `localFont` 都通过 `declarations` 写上 Google latin 块原样的 unicode-range。
- **字重写成离散的 src 条目，而不是区间**：Google CSS 为每个字重单独生成一条 `@font-face`（同一个文件，`font-weight` 分别为 400/500/600……）。这里用 `src` 数组逐条复刻，使 CSS 字体匹配规则（包括 font-bold 请求超出上限字重时的就近匹配）和改前完全一致。`next/font` 要求参数必须写成字面量（SWC 转换期序列化），不能用 `.map` 或常量，所以 unicode-range 字符串在 6 处重复，这是有意为之。
- **fallback 字体**：Google 版按字体类别选 fallback（serif 用 Times New Roman，其余用 Arial）。`next/font/local` 默认用 Arial，所以 Cormorant Garamond 和 Fraunces 要显式设置 `adjustFontFallback: "Times New Roman"`。度量值的算法不同：Google 版用 capsize 预计算值，local 版用 fontkit 从文件实时计算，数值略有差异（例如 Geist 的 size-adjust 从 104.76% 变为 106.28%，Fraunces 从 115.45% 变为 126.68%）。这些值只影响 `font-display: swap` 期间、字体还没加载完时的回退排版，字体加载完成后的渲染不受影响。
- **子集覆盖的变化（已知差异）**：配置是 `subsets: ["latin"]`，但这个参数只决定预加载哪些子集。改前 `next/font/google` 实际会把 Google 返回的所有子集都写进 CSS（cyrillic、cyrillic-ext、vietnamese、latin-ext，Geist Mono 还有 symbols2），每个都带 unicode-range。按派单「只取实际用到的、控制体积」的要求，本次只提交 latin。`localFont` 的 `declarations` 会作用到同一次调用生成的所有 `@font-face`，没办法给不同文件分别设置 unicode-range，所以一次调用也装不下多个子集。影响：latin-ext/西里尔/越南文字符（如 Ł、ő、Привет、Tiếng Việt）改为由 fallback 字体渲染。已扫描 `data/` 下 35 个样例数据文件，以及 components/app/lib 中的界面文案：没有落在这些子集里的字符（★、→、└ 等原本就不在任何子集内，改前改后一样回退），所以样例店铺的渲染不变。如果以后有运营者录入这类文字，需要另立需求，补对应子集文件（需改用多个 `localFont` 调用或手写 `@font-face`）。
- **许可**：6 款字体都是 SIL Open Font License 1.1（依据 google/fonts 仓库 `ofl/<name>/METADATA.pb` 中的 `license: "OFL"` 和各自的 OFL.txt），允许再分发，前提是许可文本随字体一起分发。Orbitron 声明了保留字体名 "Orbitron"：OFL 只限制「修改版本」使用这个名字。本次提交的是 Google Fonts 原样提供的文件，未做任何修改，并且改前 `next/font/google` 也已经把这个同样的文件从本站 `/_next/static/media` 对外提供，再分发的状态没有变化。
- **文件位置**：本版 Next（16.3.4）文档 `01-app/03-api-reference/02-components/font.md` 写明，`src` 路径相对于调用 `localFont` 的文件，字体可以和代码一起放在 `app/` 下（示例为 `app/fonts/`）。`app/fonts/` 不含 `page`、`route` 等约定文件名，不会生成路由。
- **构建产物断言的局限**：Next 自带的 `@next/font/dist/google/*.js` 会被 output tracing 带进 `.next/standalone/node_modules` 和 `.open-next/server-functions/default/node_modules`，所以这两处仍能 grep 到两个域名。这是 Next 包自身的代码，不是本应用的产物，断言时排除 `node_modules`。最强的证据是阻断两域后构建依然成功，且钩子记录为 0。

### 阻断钩子（验证用，不入库）

```js
// /tmp/fonthook/block-google-fonts.cjs：对两个域的 DNS 解析报 ENOTFOUND，并记录每次尝试
const dns = require("node:dns");
const fs = require("node:fs");
const BLOCKED = /(^|\.)fonts\.(googleapis|gstatic)\.com$/i;
const LOG = process.env.FONT_BLOCK_LOG || "/tmp/fonthook/attempts.log";
function blocked(host) {
  if (typeof host === "string" && BLOCKED.test(host)) {
    fs.appendFileSync(LOG, `${process.pid} ${host}\n`);
    const err = new Error(`getaddrinfo ENOTFOUND ${host} (blocked by font hook)`);
    err.code = "ENOTFOUND";
    err.hostname = host;
    return err;
  }
  return null;
}
const origLookup = dns.lookup;
dns.lookup = function (host, options, callback) {
  const err = blocked(host);
  if (err) {
    const cb = typeof options === "function" ? options : callback;
    process.nextTick(() => cb(err));
    return {};
  }
  return origLookup.apply(this, arguments);
};
const origPromiseLookup = dns.promises.lookup;
dns.promises.lookup = function (host, ...rest) {
  const err = blocked(host);
  if (err) return Promise.reject(err);
  return origPromiseLookup.call(this, host, ...rest);
};
```

自检：挂上钩子后，`https.get` 和 `fetch` 访问两个域都得到 ENOTFOUND，访问 example.com 正常返回 200。`NODE_OPTIONS` 会被 opennext 拉起的 `next build` 子进程继承。
